# onset-ml — Amulet XPL sleep-onset detector

Detects the moment a resting person starts to fall asleep from the glove's grip (FSR) and
finger PPG, and fires a haptic cue on the Drake LRA. Everything here runs on the laptop; the
XIAO firmware only streams samples (see `firmware-and-tools/bench3_live`).

```
onset/parse.py      bench_bridge capture CSV -> Session (100 Hz grid, beats, notes/labels); flex + PPG only, no EDA
onset/simulate.py   synthetic sessions in the same format (pipeline test data, not truth)
onset/features.py   causal windowed features, 1 row / s          <- editable by autoresearch
train.py            the detector: MODEL = 'dormio' (Horowitz 2020 sec. 2.2) | 'logreg'  <- editable by autoresearch
thresholds.py       reproduces the paper's sec. 3.3 threshold table (80th pct Sleep / 20th pct Wake) from captures
docs/dormio-method.md  what the paper says, paper vs code, what its citations support, what we took
rssi_capture.py     palm-XIAO BLE RSSI -> captures/rssi-<stamp>.csv (every sample, whole session) + live to the GUI
rssi_report.py      RSSI around every onset / report / cue label; aligned 1 Hz export + raw RSSI export per session
evaluate.py         FIXED harness: leave-one-session-out CV, latency / false alarms / misses
onset/haptic.py     decaying-beep pattern schema, presets, guard, render, serial line
live.py             live detector server + haptic controller, http://localhost:8790
gui.html            the cockpit: signals, score, arm, pattern editor, labels, probe
program.md          the autoresearch loop an agent follows
results.tsv         experiment log (untracked)
data/sessions/      REAL captures (copy from ~/Documents/Arduino/captures/)
data/synthetic/     generated by onset/simulate.py (untracked)
```

## RSSI (palm XIAO, amulet-firmware)

The palm XIAO runs the Amulet RSSI firmware (`~/conductor/repos/amulet-firmware`, BLE contract
v1.1): it is the BLE peripheral and the RSSI sensor. The laptop connects, and the XIAO measures
RSSI on every connection event (~66 Hz at 15 ms) and notifies batches every 40 ms.

```
.venv/bin/python rssi_capture.py              # BLE: scan, connect, RESET_SEQ, START, reconnect forever
.venv/bin/python rssi_capture.py --serial /dev/cu.usbmodemXXXX   # the firmware's 10 Hz USB echo instead
.venv/bin/python rssi_capture.py --demo       # synthetic, for testing the pipeline
```

Every sample is written as it arrives to `~/Documents/Arduino/captures/rssi-<stamp>.csv` with
the laptop's clock, the same clock the bench bridge stamps the sensor capture with; that is the
alignment. The firmware STATUS (granted connection interval, achieved Hz, dropped) is logged once
a second and an observed-rate / gap / batch-age line every 10 s, so rate and latency are in the
record, not assumed. If `live.py` is running, samples are also forwarded to it (fourth trace in
the GUI, status line under it, RSSI features in the detector's feature table).

Keep the capture running for the whole session. Copy `bench-<stamp>.csv` and `rssi-<stamp>.csv`
together into `data/sessions/` (rename the rssi file to the bench stamp if they differ); the
parser finds the companion by name, else by host-time overlap. Then `rssi_report.py` prints RSSI
around every label and writes `data/exports/<session>-aligned.csv` and `-rssi-raw.csv`.

## Self-training sessions (one person, no EEG)

Everything is recorded into this repo, so a session is a set of files you can commit.

1. Board flashed with `bench3_live`, plugged in. Close the Arduino Serial Monitor.
   Double-click **`Nap Session.command`**. It starts the bench bridge (USB serial -> capture), the
   RSSI capture (BLE; keeps scanning if the palm board is off) and the GUI, and opens
   localhost:8790.
2. In the GUI, type a session name and press **Start session**. Recording starts, calibration
   restarts. Lie down, hand relaxed on the flex strip, PPG on a finger, stay awake 2 min.
3. Turn the probe on (20 s). Press SPACE when you hear it. Two misses = `onset` mark.
   Label freely (A/D/H/S). Arm the cue when you trust it; answer "And were you asleep?" after
   each cue (1/2/3). Keep Dormio timing at 0 to measure latency, or 60-300 s to mimic the study.
4. Press **End session**. The files are moved into `data/sessions/` under one stamp
   (`bench-`, `rssi-`, `session-<stamp>.json`), a row goes into `data/sessions/ledger.csv`,
   and the GUI shows the summary: onset time, first detection and cue, latency, your ΔHR and
   Δflex at the first report next to the Dormio thresholds (5 bpm, 8 kΩ), the RSSI shift, and
   the cumulative 80th/20th percentile table over all your sessions so far.
5. `git add data/sessions && git commit`. Then, whenever you like:
   `.venv/bin/python evaluate.py` (harness, real sessions outrank synthetic),
   `.venv/bin/python thresholds.py --probe` (the paper's table on your data),
   `.venv/bin/python session_view.py --data data/sessions` (the review page; also at /review).

The detector stays on the Dormio baseline (`MODEL = 'dormio'`, 120 s mean, |ΔHR| > 5 bpm or
|Δflex| > 8 kΩ). The sessions are what let `thresholds.py` and the autoresearch loop re-derive
those numbers for this sensor and this person.

## Where the design comes from

- Dormio / openSleep: personal awake baseline + deviation (HBOS), per-session calibration,
  flex/HR/EDA thresholds; the three labelled test recordings there are too short to train on.
- Physiology memo (Sept 2026): grip loss and PPG amplitude rise (distal vasodilation) are the
  earliest channels; HR falls a few bpm over 1-3 min; N1 breathing turns irregular; RMSSD/HF
  barely move at N1 (they rise in N2); EDA storms are too slow for a 30 s detector.
- Ground truth: Ogilvie behavioural probe (tone every 16-30 s, missed response = asleep).
- Haptics: TITAN Drake HF, f0 160 Hz, 5-300 Hz band, 145 mA rms rated; bursts under 30 ms feel
  like taps, longer like vibration; decelerating irregular trains defeat adaptation.
